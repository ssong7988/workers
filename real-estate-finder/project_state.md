# real-estate-finder 프로젝트 상태

최종 갱신: 2026-09-02

## 목표

- 로그인된 Edge 브라우저로 네이버 부동산 관심 매물을 매시간 정각 조회한다.
- 급매는 발견 즉시 본인 카카오톡으로 알린다.
- 평일 오전 08:00에는 최신 조회 후 현재 조건을 만족하는 전체 매물을 보낸다.
- 구현 완료 직후 `smoke-test`로 실제 조회와 카카오 수신을 즉시 검증한다.
- 초기에는 로컬 파일을 사용하고 향후 PostgreSQL 및 추세 그래프로 확장한다.

## 관심 매물 기준

| 아파트·면적 | 일반층 조사 | 일반층 급매 | 저층 조사 | 저층 급매 |
|---|---:|---:|---:|---:|
| 래미안센트럴스위트 84A·84B·84C | 25억 이하 | 24억 이하 | 24억 이하 | 23억 이하 |
| 과천센트럴파크푸르지오써밋 84 전 타입 | 25.5억 이하 | 24.5억 이하 | 24.5억 이하 | 23.5억 이하 |
| 과천위버필드 84 전 타입 | 26억 이하 | 25억 이하 | 25억 이하 | 24억 이하 |

공통 규칙:

- 전용면적 84.00~84.99㎡를 84형으로 판정한다.
- 실제 1~3층 또는 숫자 없이 `저`, `저층`으로 표시된 매물은 조사·급매 기준에서 각각 1억 원을 차감한다.
- 층수가 없거나 해석할 수 없으면 조건 판정에서 제외하고 로그에 남긴다.
- 검색 URL에는 일반층 상한을 적용하고 수집 후 프로그램이 층별 기준을 다시 판정한다.
- 급매 기준과 정확히 같은 가격도 급매로 포함한다.

## 현재 구현

- `real_estate_finder/collector.py`: 새 창을 생성하지 않고 CDP로 실행 중인 Edge에 연결한다. 네이버 홈에서 화면의 `부동산` 링크를 클릭한 다음 검색창·검색 결과를 이용한다. 홈 로드 후 5초 뒤 단지명을 입력하고 입력 완료 후 15초 뒤 검색한다. 저장된 매물 URL이나 비공개 API를 직접 호출하지 않으며 CAPTCHA와 접근 제한을 우회하지 않는다.
- `real_estate_finder/parsing.py`: 한국식 가격, 전용면적, 타입과 층수 정규화.
- `real_estate_finder/service.py`: 조건 판정, 중복 확인, 급매 및 오전 보고 흐름.
- `real_estate_finder/storage.py`: 원자적 JSON 상태, JSONL 관측·실행 이력과 발송 실패 대기열.
- `real_estate_finder/notifier.py`: 기존 `kakao-notifier`를 사용하는 200자 이하 메시지 어댑터.
- `config/searches.yaml`: 확정된 세 검색 조건 템플릿. 실제 URL은 Git에서 제외된 `searches.local.yaml`에 저장한다.

명령 인터페이스:

- `browser-login`: CDP로 연결된 기존 Edge에서 네이버 로그인 상태를 확인한다. `--edge-cdp`에 빈 문자열을 주었을 때만 기존 전용 프로필 방식으로 동작한다.
- 매물 조회는 네이버 부동산 URL을 직접 열지 않고, 네이버 홈에서 화면의 `부동산` 링크를 클릭해 이동한 다음 검색창과 화면 결과를 사용한다.
- 기본 수집은 새 Edge를 띄우지 않고 CDP 포트로 이미 실행 중인 Edge와 로그인 세션에 연결하며, 외부 Edge 컨텍스트나 탭을 종료하지 않는다.
- `validate-config`: URL과 금액 등 설정 검증.
- `scan-once`: 즉시 한 번 조회하며 정규 급매 알림 규칙 적용.
- `smoke-test`: 즉시 한 번 조회하고 성공 요약 및 조건 충족 매물을 카카오톡으로 전송. 급매 발송 이력은 소모하지 않는다.
- `scheduled-run`: 시간별 조회, 급매 알림 및 평일 오전 보고.
- `send-digest`: 저장된 현재 매물을 수동 발송.

## 2026-09-02 검증 현황

- 설정 검증 성공: 활성 검색 조건 3개.
- 단위·서비스 테스트 11개 모두 통과.
- Python `compileall` 및 Git 공백 오류 검사 통과.
- `smoke-test`가 실패 결과를 카카오톡으로 보내는 흐름은 성공했으며 발송 실패 대기열은 생성되지 않았다.
- 실제 매물 수집은 아직 성공하지 않았다. 현재 실행 중인 일반 Edge에서 `http://127.0.0.1:9222` CDP 연결이 열려 있지 않아 세 조건 모두 연결 단계에서 중단됐다.
- Codex의 외부 Edge 제어 연결도 브라우저 목록이 비어 있어 기존 탭을 직접 조작하지 못했다. 사용자가 Edge 확장 프로그램을 추가했으나 현재 세션에서는 아직 연결된 Edge로 인식되지 않았다.
- 과거 전용 프로필 방식으로 실행했을 때는 로그인 만료, 네이버 검색 결과 404, 변경된 매물 카드 DOM 미탐지 문제가 확인됐다. CDP 연결이 해결된 뒤 현재 로그인 세션에서 DOM을 다시 조사해야 한다.

## 바로 다음 작업

1. Edge 확장 연결 또는 Edge의 `edge://inspect` 원격 디버깅을 활성화해 기존 로그인 세션과 제어 채널을 확보한다.
2. CDP 엔드포인트를 자동 탐색하거나 확인된 주소를 `--edge-cdp`로 전달한다.
3. `smoke-test`를 다시 실행해 네이버 홈 → 부동산 클릭 → 세 단지 검색 → 매물 카드 파싱을 검증한다.
4. 현재 화면 DOM에 맞춰 선택자를 보완하고 성공 결과 및 조건 충족 매물을 카카오톡에서 확인한다.
5. 완전 성공 후 매시간 정각 및 평일 08:00 Windows 작업 스케줄러를 등록한다.

## 완료 확인 절차

1. 단위 및 fixture 기반 통합 테스트를 통과한다.
2. 로그인된 기존 Edge의 CDP 연결을 준비한다.
3. `python -m real_estate_finder smoke-test`를 실행한다.
4. 카카오톡에서 수집·조건 충족·급매·실패 조건 수가 포함된 성공 메시지를 확인한다.
5. 조건 충족 매물이 없어도 `조건충족 0건` 성공 메시지가 오면 조회 성공으로 인정한다.
6. 조건 충족 매물이 있으면 매물별 가격, 층, 적용 기준과 링크를 확인한다.
7. 완전 성공 후 Windows 작업 스케줄러를 활성화한다.

## 향후 PostgreSQL 및 그래프

- 파일 저장소와 동일한 인터페이스의 PostgreSQL 저장소를 추가한다.
- `search_conditions`, `scan_runs`, `listings`, `listing_observations`, `notification_events` 테이블을 사용한다.
- 관측 시각은 `timestamptz`로 저장하고 검색 조건과 외부 매물번호에 고유 제약을 둔다.
- JSONL을 재실행 가능한 명령으로 이전하고 이전 전후 건수와 가격 합계를 대조한다.
- PostgreSQL 데이터로 1주·1개월 가격 분포, 중앙값, 매물 수와 가격 변동 그래프를 생성한다.
- 그래프 이미지를 카카오 메시지로 발송한다.

## 운영 제약

- 네이버 이용약관은 사전 허락 없는 자동 검색·수집을 제한한다. 운영자는 사용 권한을 확인해야 한다.
- CAPTCHA, 비정상 접근 경고, 로그인 만료 또는 불완전 조회 시 기존 정상 상태를 덮어쓰지 않는다.
- 네이버 계정 비밀번호는 프로그램 설정에 저장하지 않고 로컬 Edge 프로필만 사용한다.
- 카카오 비밀정보와 토큰, 브라우저 프로필, 실제 검색 URL 및 런타임 데이터는 Git에 포함하지 않는다.
